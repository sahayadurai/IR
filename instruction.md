# Project Guide: FIFA World Cup 2022 Multimedia Knowledge Graph

This project follows the Information Retrieval exam handout:
[`dataset/IR_Exam_project_RUSSO2_v2.pdf`](./dataset/IR_Exam_project_RUSSO2_v2.pdf).
It implements the required source preprocessing, global ontology, RDF construction,
Graph Database storage, semantic queries, benchmark evaluation and final report.

## Source data

The professor-provided local collection contains:

- Historical FIFA World Cup results and tournament summary.
- FIFA World Cup 2022 team standings.
- FIFA World Cup 2022 player statistics.
- The FIFA World Cup 2022 all-player name/image dataset.

The handout also requires `jfjelstul/worldcup`. The repository provides match, goal and
player-appearance records. Run `python scripts/fetch_worldcup_data.py` to fetch the
three required CSV files from pinned commit
`35a8667f518b07469182ae16d35574dd0e7a00fb`. The graph builder selects the `WC-2022`
records. This adds match-level facts without pretending that team standings are
individual match results.

## Ontology

Core classes: `Tournament`, `Team`, `TeamTournamentStatistics`, `Player`, `Match`,
`Goal`, `Appearance`, `Venue`, `Club`, `Image` and `Dataset`.

Core links include:

- `Match --matchOf--> Tournament`
- `Match --homeTeam/awayTeam--> Team`
- `Match --playedAt--> Venue`
- `Match --hasGoal--> Goal --scoredBy--> Player`
- `Appearance --appearanceOf--> Player`
- `Appearance --appearanceIn--> Match`
- `Player --representsTeam--> Team`
- `Player --playsForClub--> Club`
- `Player --hasImage--> Image`
- `Team --hasTournamentStatistics--> TeamTournamentStatistics --inTournament--> Tournament`
- `Entity --wasDerivedFrom--> Dataset`

RDF `rdf:type` triples identify classes. Attribute predicates link to RDF literal values.
The illustrated schema is in [`report.md`](./report.md) and the generated
[`report.pdf`](./report.pdf).

## Build and run

1. Install Neo4j locally and configure `.env`. Copy `.env.example` to `.env` if needed,
   then set `NEO4J_PASSWORD` to the password configured in Neo4j.
2. Run `./run.sh`. It installs Python requirements, fetches missing match-source files,
   builds `fifa_kg.ttl`, imports the graph, runs the benchmark suite, generates
   `report.pdf`, and starts Streamlit on `http://localhost:8501`.
3. The run script uses `python src/neo4j_import.py --replace` behavior: it deletes all
   graph data in the selected Neo4j database before import. Use this only with the
   project database. The importer without `--replace` is additive.

For separate stages:

```sh
python -m scripts.fetch_worldcup_data
python -m src.run_pipeline
python src/neo4j_import.py
python -m scripts.evaluate --repeats 5
python -m scripts.build_report
```

The pipeline writes `output/data_quality.json`. The evaluator writes
`output/evaluation.json` and exits nonzero when a result differs from source-derived
ground truth. The report generator requires the evaluation output and includes measured
query results and timings.

## Retrieval and evaluation

The dashboard's Cypher page runs queries in a Neo4j read transaction. The
[`cyphers.md`](./cyphers.md) catalog includes queries for historical champions, 2022
team standings, match/venue facts, scorer and appearance retrieval, player profile,
image descriptors and provenance. The benchmark suite covers the separate datasets and
reports correctness plus median local response time. LLM fluency is not an evaluation
metric.

## Multimedia descriptor

One lexicographically selected JPEG per player image folder is described using original
dimensions, image count, relative path and a normalized 24-value RGB histogram (8 bins
per channel, from a 64×64 thumbnail). The histogram is deliberately simple and
interpretable. It is not a learned embedding or face-recognition feature.
